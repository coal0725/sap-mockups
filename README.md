# SAP 개선안 시안

삼성표준인증원 SAP 인증심사 플랫폼의 **화면 개선안 시안**입니다.

> 삼성표준인증원 장은수 · 2026-10-06
> 문의 ssr@ssr1.co.kr

---

## 이 시안의 성격

**확정안입니다.** 참고안이 아닙니다.

시안은 아래 항목의 기준입니다.

- 화면 구성 · 문구 · 배치
- 필수 여부 — `data-req` · `data-reqgroup` 속성
- 조건부 표시 규칙 — `data-when="필드:값"` 속성
- 네비게이션 약어 — `data-nav` 속성
- 상태 분기 — `data-state` 속성

**스타일은 참고용입니다.** 통째로 복사하지 마시고 프로젝트 구조에 맞게 옮겨 주십시오.

### data-state 에 관하여

`SC-007` · `SC-008` 의 상태 표시는 **표시 문자열이 아니라 `data-state` 속성으로 분기**하도록 만들었습니다.

```html
<span class="cs-state" data-state="valid">유효</span>
<span class="cs-state" data-state="suspended">정지</span>
```

문구가 바뀌어도 화면이 깨지지 않습니다. 표시 문자열로 조건을 걸지 마시기 바랍니다.

## 마이페이지 — SC-030

### 블록 구성

다섯 개 블록을 세로로 배치합니다.

```
요약     자격 신청 · 코드 신청 · 보고서 작성 · 예정 심사 · 신규 공지
①       기본 정보          증명사진 · 서명 · 연락처 · 주소
②       소속 정보          복수 등록 · 카드형 · 첫 소속만 펼침
③       학력 · 근무경력 · 자격증
④       자격 등록          표준별 자격등급 · 유효기간 · 갱신일자
⑤       코드 등록          인증수행범위 · 세분류
```

요약 칸은 집계 숫자이자 바로가기입니다 — 자격 신청 현황 · 코드 신청 현황 · 심사보고서 조회 목록 · 일정 캘린더 · 게시판으로 각각 이동합니다.

### 입력 경계

**블록 ①②③ 과 ④⑤ 는 성격이 다릅니다.**

| 블록 | 입력 주체 | 승인 | 상태값 |
|---|---|---|---|
| ①②③ | 심사원 본인이 자유롭게 입력 | 없음 | 없음 |
| ④⑤ | 심사원이 신청 → 인증원이 승인 | 있음 | 있음 |

①②③ 은 증빙이 필요하면 인증원이 별도로 요구합니다. 본인 입력을 승인 대상으로 만들지 마십시오.

단, **②의 일부 항목은 인증원에서만 변경**합니다 — 소속기관 · 재직상태 · 입사일 · 고용형태. 화면에서 숨기지 않고 수정 모달에서 비활성 입력란으로 표시해 주십시오.

### 모달과 화면의 구분

```
모달        기존 정보 수정 (①②③) · 등록된 자격 · 코드의 상세 조회
별도 화면   신규 · 갱신 신청 · 신청 내역 조회
```

신청은 제출 후 되돌릴 수 없고 승인 절차가 뒤따르며 작성 중 이탈 후 복귀가 필요합니다. 주소가 남아야 합니다.

**조회 모달과 편집 모달의 닫힘 조건도 다릅니다.** 조회 모달은 배경 클릭과 `ESC` 로 닫히고, 편집 모달은 「취소」 또는 「저장」으로만 닫힙니다. 입력 중 배경을 잘못 눌러 작성 내용이 사라지는 것을 막기 위함입니다.

### 시안 여는 방법

모달은 다음 경로로 열립니다.

```
블록 머리글의 ✎수정        기본 정보 · 소속 정보
소제목 옆의 ✎수정          학력 · 근무경력 · 자격증
표의 행 클릭               자격 상세 · 코드 상세
헤더 드롭다운              비밀번호 변경
```

## 역할별 사이드네비 — CM-nav

상단 탭에서 역할을 전환해 주십시오. `PA → A → LA → VA → MN → MS` 순입니다.

### 포함관계

```
심사 계열   PA ⊂ A ⊂ LA ⊂ VA
관리 계열   MN ⊂ MS
```

**두 계열은 교차하지 않습니다.** ISO/IEC 17021-1 상 심사 수행과 인증 결정은 분리되어야 하므로, 심사원 계정에 관리 메뉴가 보이거나 그 반대가 되어서는 안 됩니다.

동일인이 두 역할을 수행하는 경우 **영역 전환 기능을 두지 않고 계정을 각각 생성**합니다.

### 구현 방식

**메뉴 트리는 한 벌만 두고 역할에 따라 항목을 숨겨 주십시오.** 역할별로 별도 구성을 만들면 메뉴가 하나 추가될 때마다 여섯 벌을 모두 수정해야 합니다.

선임심사원(LA)과 심사원(A)의 차이는 **메뉴가 아니라 보고서 화면 내 제출 권한**으로 구분합니다.

## 화면 번호 규칙

**문자 접미사가 붙은 화면은 기능정의서에 없는 신설 화면입니다.**

```
SC-006B   제출 완료 · 접수번호 안내
SC-010B   인증변경 접수 완료
SC-020B   계정 잠금 안내
```

세 화면 모두 기능정의서에 이동 가능 화면으로만 적혀 있거나 분기 상태로만 언급되어 있고 화면 ID 가 부여되어 있지 않아 신설하였습니다. 선행 화면이 명확하므로 그 번호에 문자를 붙였습니다.

`SC-192` 는 선행 화면이 없는 공통 화면이므로 빈 번호를 부여했습니다. 이 화면도 신설입니다.

### SC-011 인증변경 상세 신청

기능정의서 화면흐름에 `/change/form/detail` 로 적혀 있으나 **삭제 대상으로 판단했습니다.**

변경신청서 서식이 신청서와 확인서가 한 장으로 묶인 양식이므로 화면을 두 장으로 나눌 이유가 없습니다. 해당 경로는 현재 404 입니다.

### SC-031 기본정보 수정

현재 `/my/update` 로 구현되어 있으나 **마이페이지 블록①의 모달로 흡수됩니다.**

두 경로가 모두 남으면 진입 경로가 분산되고, 한쪽만 수정하면 항목이 어긋납니다. 기존 화면은 제거해 주십시오.

### SC-009 인증현황 상세

현재 구현에 `/cert/detail` 이 있으나 **시안을 만들지 않았습니다.**

대외 공개 범위(SSR-P-901 3.2.2)가 6개 항목뿐이어서 목록에 모두 담기고, 상세 화면에 추가로 보일 정보가 없습니다. 상세 화면 삭제 여부는 검수 항목 `SC009-01` 에서 판단을 요청드렸습니다.

## 시안 여는 방법 — SC-007 · SC-008

**두 화면은 독립 페이지가 아니라 웰컴 화면 위에 열리는 오버레이입니다.**

링크를 누르면 웰컴 화면이 먼저 보입니다. 화면 **하단의 검은 막대**에서 상태를 골라 주십시오.

```
SC-007   조회 입력 · 계약 검토 중 · 반려 · 계약 확정 · 심사 진행 중 ·
         시정조치 필요 · 인증 결정 완료(2차) · 인증 거부(2차) ·
         조회 실패 · 접수번호 찾기 · 발송 완료

SC-008   검색 입력 · 조회 결과 · 결과 없음

SC-020   로그인 · 빈 칸 안내 · 로그인 실패 · 잠금 안내(SC-020B)
```

그 막대는 **시안 확인용이며 구현 대상이 아닙니다.**

`SC-010` · `SC-010B` · `SC-030` · `CM-nav` 는 오버레이가 아닌 **독립 페이지**이므로 링크를 누르면 바로 열립니다.
`SC-010` 은 인증번호 뒤 5자리에 `00422` 를 넣고 「인증 확인」을 누르시면 조회 결과가 표시됩니다. `29999` 를 넣으면 정지 · 취소 안내가 표시됩니다.

### 왜 오버레이인가

`SC-007` · `SC-008` 두 화면 모두 웰컴 화면에서 직접 진입합니다. 별도 페이지로 이동하면 기업이 신청 흐름에서 이탈한 것으로 느끼고, 닫은 뒤 돌아갈 곳이 명확하지 않습니다.

닫는 경로는 세 가지를 모두 두었습니다 — `X` 버튼 · 배경 클릭 · `ESC` 키.

## 화면 순서에 관하여

**서류 첨부(SC-005)가 계약서 서명(SC-004)보다 앞입니다.**

계약서에 들어가는 심사 범위와 비용 근거가 첨부서류로 확정되기 때문입니다. 기능정의서의 화면 번호는 반대로 되어 있으며 문서 정정 대상입니다. 화면 ID 는 기능정의서를 따르되 진행 순서는 위 표를 따릅니다.

## SC-006B 에 관하여

현재 구현에 없는 화면입니다. 기능정의서 「5. 화면 흐름」에 SC-006 의 이동 가능 화면으로 「접수번호 안내」가 적혀 있으나 화면 ID 가 부여되어 있지 않아 신설하였습니다.

최종 제출 후 웰컴 화면으로 돌아가면 접수번호를 전달할 수 없고 제출 여부도 알 수 없어, 기업이 같은 신청을 다시 하게 됩니다.

## 오류 화면 — SC-192

한 화면에 네 가지 상태를 둡니다. 하단 막대에서 골라 보실 수 있습니다.

```
404 페이지 없음   500 시스템 오류   작성 시간 경과   점검 중
```

**이 화면은 헤더 · 푸터 · 사이드네비 · 웹폰트를 두지 않습니다.** 오류 화면이 다른 컴포넌트에 의존하면 그 컴포넌트가 오류의 원인일 때 오류 화면 자체가 깨집니다. 500 인데 헤더를 그리려다 다시 실패하면 백지가 뜹니다. 껍데기가 없으므로 비회원 화면과 로그인 뒤 화면에서 같은 파일을 그대로 쓰실 수 있습니다.

다른 시안과 글꼴이 조금 다르게 보이는 것은 의도한 것입니다. 웹폰트를 외부에서 받아오지 않고 시스템 폰트만 씁니다.

문구는 **제목 한 줄 · 설명 한 줄**로 유지했습니다. 전 화면 공통으로 쓰므로 신청 전용 안내가 들어가면 심사원 · 관리자 화면에서 맞지 않습니다. 점검 예정 시각도 표시하지 않습니다 — 점검은 예정보다 길어지는 일이 흔해 틀린 시각이 뜨는 것이 시각이 없는 것보다 나쁩니다.

**오류 화면에는 마스코트를 쓰지 않습니다.** 막힌 사람에게 캐릭터가 웃고 있으면 상황이 가볍게 읽히므로 로고만 두고 문구로 전달합니다. 완료 화면(`SC-006B` · `SC-010B`)에만 마스코트를 씁니다.
